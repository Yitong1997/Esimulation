# Zemax 反射光路坐标与 POP 自由空间传播修正设计

日期：2026-07-13  
状态：已获用户授权，待实现

## 1. 目标

解决反射光路中 POP API 与 Zemax ZBF 物理场不一致的问题，并使同一套逻辑能够处理
后续的多次反射、坐标旋转和非轴对称光场。

当前最明确的错误是：

1. ZBF 和 Zemax 报告使用局部坐标中的有符号纵向位置与传播距离；
2. `OpticalAxisState.path_length` 表示沿实际光线增加的正光程；
3. 当前自由空间传播把正光程直接传给了使用局部坐标的 PROPER 光束参数；
4. 反射后局部 $z$ 轴可能与实际光线方向相反，导致二次参考相位和束腰位置的符号错误。

修正目标不是在菲涅尔公式中加入“反射次数符号”，而是使坐标、光程、参考相位和复场
始终使用同一套约定。

## 2. 物理和坐标约定

每个传播状态同时保存两种量：

- `physical_path_length_mm`：沿实际光线方向累积的正光程，用于几何距离和报告；
- `signed_coordinate_distance_mm`：在当前 Zemax 局部纵向坐标中的有符号距离，用于
  PROPER 的局部光束参数和自由空间传播。

对一段自由空间，定义

$$
\sigma=\operatorname{sign}(\hat{d}\cdot\hat{z}_{\mathrm{local}}),
\qquad
d_{\mathrm{local}}=\sigma d_{\mathrm{physical}},
$$

其中 $\hat d$ 是实际光线方向，$\hat z_{\mathrm{local}}$ 是该段原始局部坐标的
$z$ 轴。$\sigma$ 由几何方向自动计算，不由表面编号或反射次数推断。

二次参考相位仍然是普通菲涅尔传播中的

$$
Q(r)=\frac{k r^2}{2d_{\mathrm{local}}}.
$$

因此，反射后的负号来自有符号坐标距离，而不是对标准菲涅尔公式另外增加一个经验符号。

## 3. 代码结构

### 3.1 光轴状态

扩展 `OpticalAxisState`，保存当前段所依据的原始局部 $z$ 轴。保留现有的
`frame` 作为实际光束的右手横向坐标系，不把二者混为同一个量。

新增辅助逻辑：

1. 对局部 $z$ 轴归一化并检查其长度；
2. 计算实际传播方向与局部 $z$ 轴的内积；
3. 当内积接近零时立即报错，禁止在未定义的传播方向上猜测符号；
4. 将该符号写入传播状态和诊断记录。

`_build_optical_axis_states` 使用表面原始方向保存局部坐标轴，不能使用已经为了
光线追迹而翻转过的 `canonical_orientation` 替代它。

### 3.2 自由空间传播

`_compute_signed_distance` 改为：

1. 先计算正的实际光程；
2. 从当前传播状态读取坐标符号；
3. 返回“坐标符号乘以实际光程”；
4. 在日志中同时输出正光程、有符号距离和符号来源。

`propagate_free_space`、`PilotBeamParams.propagate` 和 PROPER 的 `wfo.z` 必须使用同一
有符号距离。不得单独修改傅里叶核或加入反射次数符号。

### 3.3 ZBF 输入边界

`ZbfSource` 增加坐标上下文接口。ZBF 文件本身不能独立确定其局部 $z$ 轴与实际光线
方向的关系，因此：

1. 完整系统传播时由系统光轴状态提供该上下文；
2. 从某个中间 ZBF 面开始传播时，调用者必须提供对应的源面坐标上下文；
3. 不能根据 `zx` 的正负猜测反射状态；
4. 读取的参考相位、去参考相位复场和 PROPER `wfarr` 必须显式标记其表示类型。

第一阶段保留现有 ZBF 数值缩放，先修正坐标符号；共轭、单元能量归一化和参考相位转换
通过独立单元测试锁定，避免把幅度标定问题与坐标问题混在一次修改中。

### 3.4 反射面的横向坐标变换

反射后不能默认保留数组索引。对于入射和出射的右手横向基，定义

$$
T=E_{t,\perp}^{\mathsf T}E_{s,\perp}.
$$

输出坐标 $u_t$ 对应的输入坐标为 $u_s=T^{\mathsf T}u_t$。

实现分两级：

1. 对纯旋转、翻转和转置，使用无插值的整数网格变换；
2. 对一般二维正交变换，使用明确的坐标重采样，并记录插值误差和边界损失。

该变换同时作用于振幅、物理相位和 PROPER 内部复场。轴对称场可以掩盖此错误，测试中
必须加入非对称复场。

### 3.5 反射后的 PROPER 状态同步

理想平面镜当前只更新 `PropagationState.phase`，但没有同步 `proper_wfo.wfarr`。
修正后，反射面完成横向坐标变换和镜面相位后，必须从当前物理场重新构造与当前
PROPER 参考相位配套的 `wfarr`，再进入下一段自由空间。

## 4. 错误处理

- 缺少局部坐标轴时，只有兼容旧 API 的明确正向源状态可以使用默认值；中间 ZBF 源不
  得静默猜测。
- 局部 $z$ 轴与光线方向近似正交时抛出异常。
- 发现传播状态的有符号距离、光束参数和 `wfo.z` 不一致时抛出异常。
- 非正交横向变换或重采样越界必须产生诊断记录，不能静默裁剪。
- 不实现经验性的 `sign = (-1) ** reflection_count`。

## 5. 测试和验收

### 5.1 单元测试

1. 正向无反射：有符号距离等于正光程；
2. 单平面镜：实际光程为正、局部坐标距离为负；
3. 两次反射：每段符号由方向内积得到，不依赖反射次数；
4. 坐标旋转和横向翻转：非对称复场变换后逐点一致；
5. ZBF 源边界：缺少坐标上下文时失败，提供上下文时参考场闭合；
6. 理想镜后 `state.phase` 与 `proper_wfo.wfarr` 重构出的物理场一致。

### 5.2 回归验证

1. 运行全部现有 Python 测试；
2. 重新运行完整 POP API 仿真；
3. 使用同一仿真的 Zemax ZBF 终点场比较振幅、强度、物理相位和复场误差；
4. 单独检查 S7→S8 的有符号距离是否为 -368.6 mm；
5. 对 S12→S13、S13→S14 和至少一段反射后自由空间分别输出坐标符号收据；
6. 与完整角谱基线比较，确认代码没有把“匹配 Zemax”误写成“物理精度提高”。

## 6. 实施边界

本设计不改变 ZBF 文件格式，不把 RS-I 重新引入，也不把负号硬编码为某个表面或某次
反射的特殊规则。若完整仿真仍有残差，下一步只根据坐标收据、场表示类型和端面物理场
比较继续定位，不通过拟合距离或参考半径掩盖误差。
